# iOS 锁屏实时活动与灵动岛设计

日期：2026-11-27
状态：维护者已确认课名优先方向；本文不是实现或验收完成证明。

## 意图

以 `ios-live-activity-stretched-small`（`fca72f61`）为代码基线，让学生在不解锁手机的情况下先看清“现在该做什么、何时变化”，再按需要展开看课程和下一项安排。保留现有课表快照、加密存储、分段切换和点击打开应用的链路；锁屏采用维护者确认的课名优先布局，灵动岛独立分区，同时修复展示状态中的隐私与去重缺口。

## 目标

- 锁屏实时活动保留桌面小号「接下来」的大时刻，以色条中的课名为视觉中心、地点为次行，同时只保留一处倒计时。
- 灵动岛分别设计展开、紧凑和最小形态，不再把整张锁屏卡片直接塞进展开底部区域。
- 上课中、未上课、课间、长课名、无地点、无下一项和隐私状态都有可检查的预览。
- 保留现有 `ubaa://widget/open?` 深链与主项 `privacySensitive` 行为。
- 修复私密下一项标记在实时活动投影中丢失的问题；仅隐私标志或深链变化时也必须刷新旧活动。

## 非目标与反目标

- 不新增学校请求、Bridge/CLI 字段、推送、后台刷新或新的持久化。
- 不改变 `ScheduleLivePlan` 的分段、8 小时窗口、当前与下一段的调度语义；不把“每次最多预约下一次”扩大成持续后台自动换完整课表。
- 不在本轮新增默认提示音、失败提示或第三段接续调度；这些行为如需改变另行确认。
- 不新增主题、渐变、装饰图标堆叠或每秒多处跳动的计时器。
- 不用模拟器截图冒充真机锁屏、Keychain 共享或灵动岛验收。

## 现状与问题

- `ios-notification-center-widget`（`9eee0e4b`）→ `ios-live-activity-course-center`（`c468f563`）→ `ios-live-activity-stretched-small`（`fca72f61`）是线性提交，不是两个独立功能分支。
- 数据模型 `ScheduleLiveFace` 已有时刻、完整课程时间、课名、地点、教师、下一项、本节与本堂结束时间，无需扩展合同。
- 最新锁屏视图左侧沿用桌面小卡的计时文案，右侧又显示同一目标的倒计时，信息重复。
- 灵动岛已有 compact/minimal 文案，但展开态只有一个 bottom region；内容层级与锁屏相同，未利用 leading/trailing 区域。

## 方案比较

### 采用：课名优先的拉宽小卡 + 独立灵动岛层级

在最新代码基线上把锁屏色条内改为课名第一、地点第二，右侧保留状态和唯一倒计时；灵动岛按系统区域拆分。该选择来自维护者对 mockup 的确认。优点是课名识别直接、扫视路径明确，且不需要回退后续提交。代价是锁屏和灵动岛不再完全复用同一视图，需要各自预览。

### 不采用：保留地点优先

`fca72f61` 与桌面小卡顺序一致，但维护者在看图后明确选择课名优先，因此不再把地点优先作为本任务目标。

### 不采用：三版都继续保留并分别迭代

三条提交只改同一个 SwiftUI 视图，继续并行会增加重复修正和合并成本。先确定一个基线，再由 Git 历史保留其他方案。

## 视觉令牌

沿用 `SchedulePalette.resolve(theme: .ocean, accented: false)`，不新增颜色系统：

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| Canvas | `#ECF3FB` | `#0E1826` | 锁屏活动底色 |
| Ink | `#1C293B` | `#F0F5FA` | 主时刻、课名、展开态标题 |
| Secondary | `#526980` | 白色 68% | 地点、辅助时间 |
| Accent | `#256EDC` | `#8EBEFF` | 状态、倒计时、4pt 色条 |

字体继续使用系统 SF 与中文系统字体：24pt（锁屏）半粗主时刻，15pt 半粗课名，13pt 地点，11–13pt 辅助文案；灵动岛按区域缩小到 20pt 以内。时间和倒计时使用等宽数字。compact/minimal 使用系统推荐的小字号和 SF Symbols，避免长文本缩成不可读的小字。

## 锁屏布局

左对齐；主时刻与课名形成第一视觉层，右侧只显示状态与一份倒计时。课名和地点共用现有 4pt 色条，下一项最多一行。

未上课：

```text
08:00–09:35                         接下来
                                    还有
▍高等数学                         18分20秒
▍主楼 A201
下一节 10:10 大学英语 教一 B305
```

上课中：

```text
至 09:35                            进行中
本节至 08:45                        还剩
▍高等数学                         12分08秒
▍主楼 A201
下一节 10:10 大学英语 教一 B305
```

规则：

- 右侧倒计时继续用现有 `ScheduleLiveClock.remaining`，保持「分秒／时分」文案；删除左侧重复的同一目标倒计时。
- 未上课主时刻用现有 `primary.timeText` 与 `endText` 组成完整时段；已经包含结束时刻时不重复拼接，不新增输入字段。
- 上课中副行显示本节结束；未上课不再额外重复「还有」。
- 没有对应字段时整行省略，不留下空白占位；没有下一项时允许课名使用现有第二行空间。

## 灵动岛布局

### 展开

leading 放课名与地点，trailing 放状态和系统计时，bottom 放完整课程时间与下一项。课名继续使用 `privacySensitive(face.isPrivate)`；compact/minimal 不显示课名。

```text
┌ 高等数学                         进行中 ┐
│ 主楼 A201                       还剩 12:08 │
│ 08:00–09:35 · 本节至 08:45                 │
│ 下一节 10:10 大学英语 教一 B305             │
└───────────────────────────────────────────┘
```

- 有有效倒计时目标时使用 `Text(timerInterval:countsDown:)`，让系统更新，不另开 `TimelineView`。
- bottom 最多两行；没有下一项时只保留时间行。
- 长课名、长地点和下一项均单行截断／缩放，不能挤压 trailing 的状态与时间。

### 紧凑与最小

- compactLeading：进行中使用 `timer`，未上课使用 `calendar`，颜色取 Accent。
- compactTrailing：有有效目标时显示系统倒计时，否则显示最近的有效上课／下课时刻；不显示完整课名或完整时间段。
- minimal：只显示同一状态符号，不放入会截断的长时刻。
- 三种形态均保留现有点击深链。

## 共同隐私与刷新修复

审查发现 Dart 和 Swift 输入模型已经有 `secondary.private`，但 `ScheduleLiveFace` 没保留它，锁屏／灵动岛副行也未调用 `privacySensitive`。实施时先写失败反例，再做最小修复：

- 给 `ScheduleLiveFace` 增加向后兼容的 `secondaryPrivate: Bool? = nil`，从既有副行字段投影；旧 ContentState 缺少字段仍须可解码，现有预览构造也可省略该参数。
- 锁屏与灵动岛的下一项文本按 `secondaryPrivate == true` 使用系统隐私遮盖。
- 新 compact/minimal 不选择课名，从展示路径消除原有 compactTrailing 在「未上课、无地点、有结束时刻」时漏标私人标题的问题。
- 去重键补上 `link`、`isPrivate`、`secondaryPrivate`，防止只改这些字段时被误判为相同活动；测试先证明旧键会漏掉这些变化。

纯布局、字体和颜色调整复用现有视图编译与预览；状态字段、投影和去重行为必须先 RED 后 GREEN。Android 的私密副行是另一个平台边界，本轮不用 iOS 修复代替 Android 决策。
